# Agent Arena 前端重设计规格 · 全息议事舱

> 本文档是给前端开发的实现规格。所有颜色、字号、动效参数、线框、文案都已定稿，照做即可，不需要再设计。
> 覆盖范围：全局外壳 + 五个页面（登记 / 会场 / 记录 / 档案 / 模型）。核心是**会场页的圆桌会议场景**。

---

## 0. 一句话定位

把 Agent Arena 从"站在一条金属轨道上看模型站位"，改造成"钻进一间全息议事舱，围着一张发光圆桌看机器人代表彼此交锋"。

观众要 feel 到的三件事：**这真的是一场会**（有座位、有先后、有绕桌的视线）、**这些真的在思考**（思考、犹豫、被打断、被投票出局）、**这局有分量**（被淘汰的席位会真的塌掉、被淘汰的模型留下评审席的投票权）。

---

## 1. 气质定调

**主题物**：不是"数据仪表盘"，不是"聊天气泡列表"，而是**一间地下议事厅里的全息圆桌**。参考感觉是联合国安理会圆桌厅 + 舰桥全息投影 + 老式议会辩论的座位秩序。三者的交集。

**关键词**：黑曜石、玻璃、刻线、边缘光、数据环、体积光、低频呼吸、精密。

**明确排除**：SaaS 卡片堆、渐变按钮、圆角药丸标签、玻璃拟态毛玻璃、任何 emoji 图标、任何"AI 风格"的紫粉渐变。

**为什么选青色而不是常见的酸绿/朱红**：全息投影膜的经典色是青绿（cyan-green），它的发光是冷色叠加，不是实心色块。所以本设计里青色**从不作为面填充出现**，只以细线、边缘辉光、体积光柱的形式存在；信息密度靠明度层级而不是色相数量去撑。

---

## 2. 设计原则（写给开发的硬约束）

1. **一个 memorable，其余安静。** 视觉预算全部花在圆桌场景上。记录页、档案页、模型页是同一套仪器的面板，克制、精确、无装饰。任何一个页面都不允许出现第二种"炫技"元素。
2. **颜色属于模型，不属于界面。** 界面只有三个语义色（在线青 / 危险品红 / 中性灰蓝），其余彩色全部由参赛模型的身份色占据。模型的颜色在名册、圆桌、记录、投票连线里必须完全一致。
3. **动效必须回答"发生了什么"。** 每个 SSE 事件触发一个具体动作：谁在说话、谁在思考、谁投给了谁、谁出局。禁止无触发源的循环炫技动画（除了桌面数据环本身极慢的自转）。
4. **状态用形状和明度表达，不用文字标签堆砌。** 出局 = 去色 + 座位下沉 + 圆环断裂。领先 = 双环。思考 = 断续旋转环。文字只用来承载语义（模型名、理由、票数）。
5. **信息层级靠留白和线，不靠卡片。** 全站不使用"一排等大圆角卡片"；分栏用发丝线和背景明度差。
6. **可读优先于氛围。** 正文任何时候都不低于 13px / 对比度 ≥ 4.5:1；全息效果只作用于装饰层和短标签，不作用于长段落的可读性。

### 3.4 动效令牌

```
--dur-instant  120ms   状态切换
--dur-fast     240ms   悬停、按下
--dur-base     420ms   常规转场
--dur-slow     720ms   场景级变化（座位重排、面板升起）
--dur-cinema  1400ms   开场序列

--ease-out    cubic-bezier(.16,1,.3,1)      进入
--ease-in     cubic-bezier(.7,0,.84,0)      离场
--ease-spring cubic-bezier(.34,1.56,.64,1)  弹跳（仅座位重排、票数跳变）
--ease-linear                                持续循环（数据环）
```

**`prefers-reduced-motion: reduce` 时**：所有位移归零、缩放归一、循环动画停止、闪烁停止，仅保留 120ms 的透明度切换与颜色变化。内容必须完全可读、状态必须完全可辨识。

## 4. 全局外壳

整站是**一个控制台**，不是五个网站。顶部是一条 56px 的固定轨道，页面在其下切换。

```
┌──────────────────────────────────────────────────────────────┐
│ ◈ AGENT ARENA   命题与名册 │ 会场 │ 记录 │ 档案 │ 模型   ◉ 声音│ 56px
└──────────────────────────────────────────────────────────────┘
   ↑ 左侧品牌         ↑ 中段导航（分段轨道）              ↑ 右侧遥测
```

**品牌区**：`◈` 用一个 18px 的线框菱形（SVG，非图标字体），右侧 `AGENT ARENA` 用 Space Grotesk 700，字距 0.02em，14px，`--ink`。下方不加"多智能体辩论赛"副标题——它在 README 里已经有了，界面上是废话。

**导航**：不是按钮列表，是一条**分段轨道**（segmented rail）。底是一条 1px 发丝线，当前页下方是一段 24px 宽的青色实线，切换时这条线用 `--dur-base` 平滑滑移。导航项右侧的角标保留但改形：直播中用一个 5px 青色圆点（带 2s 呼吸），轮次用一个 mono 数字。

**声音开关**：右上角，mono 小字 `◉ 声音` / `○ 静音`，点击时图标做一次 180° 旋转 + 淡出淡入。

**页面容器**：最大宽度 1360px，居中，左右 padding 32px（移动端 16px）。会场页例外——**全出血铺满**，不设最大宽度。

### 5.2 场景分层（从后到前）

| 层 | 内容 | 实现要点 |
| --- | --- | --- |
| L0 背景场 | 深空渐变 + 极淡网格地平线 | `radial-gradient` + 1px 网格线，透明度 ≤ .05，指针视差 ±6px |
| L1 体积光 | 从顶部落下的锥形光柱，照亮桌面 | `conic-gradient` + `mix-blend-mode: screen`，带 6s 缓慢呼吸（opacity .8→1） |
| L2 桌面 | 椭圆玻璃盘 | `transform: rotateX(56deg)`，父级 `perspective: 1200px` |
| L3 桌面纹理 | 3 圈同心刻线环 + 一道缓慢反向自转的虚线扫描环 + 中心一个细十字准星 | SVG，最外圈 `24s` 正转，扫描环 `17s` 反转 |
| L4 立场场 | 桌面上叠加一层极淡的立场渐变（左=支持 / 右=反对），中央 50% 区域透明 | 取代旧版"立场轴"，数据仍来自 `stances`，没有立场数据时整层 `opacity: 0` |
| L5 座位环 | 每个模型一个座位 | 见 5.3 |
| L6 投票射线 | 投票人座位 → 被投座位 的弧线 | SVG `path` + `stroke-dasharray` 描边动画 |
| L7 投影面板 | 当前发言文字 | 屏幕平面，不随桌面倾斜，保证可读 |
| L8 HUD | 顶条、计时、回放控制 | 固定 |

**桌面盘面细节**：
- 椭圆宽 `min(920px, 68vw)`，高 = 宽 × 0.52。
- 边缘 1.5px 青色描边，外加一圈 `blur(14px)` 的同色辉光（`--live-glow`，opacity .45），辉光带 3.2s 的极缓呼吸。
- 盘面填充 `rgba(10, 20, 30, .72)` + 一层 `repeating-radial-gradient` 的等高线纹（间距 6px，透明度 .022），像全息投影的干涉纹。
- 盘面下方有一层 `transform: translateZ(-30px)` 的倒影椭圆（亮度 30%），做"桌体厚度"。
- **不要**在桌面放任何实心色块。

### 5.3 座位几何

设参赛人数 `n`，座位索引 `i`（按登记顺序，索引固定，不随轮次移动）。

```
φ_i  = -90° + (360° / n) × i        // 座位角
x_i  = cx + Rx × cos(φ_i)
y_i  = cy + Ry × sin(φ_i)            // 场景坐标，未 tilt
scale_i = 1.0                        // 前景座位（下半圈，sin φ > 0）
scale_i = 0.86                       // 后排座位
opacity_i = 1.0 / 0.74
```

- 座位环椭圆半径：`Rx = 桌面宽 × 0.52`，`Ry = 桌面高 × 0.60`。
- **标签避让**：后排座位（`sin φ < 0`）的名字标签放在座位**上方**，前排放**下方**；标签始终水平，不随场景倾斜。
- 座位锚点用 `transform: translate(-50%, -50%)` + 单独的 `scale` 变量控制纵深，不要把 scale 写进 translate 里，避免多次 transform 覆盖。

**座位组件解剖**（每个座位是一个 `<div class="seat">`）

```
        ╭─ 悬名标签（后排在上方）
        │   GPT-5
   ◍    │  ← 椅子底盘：椭圆，模型色 12% 透明度
 [机器人头纹]
        │   ◦◦◦   ← 收到的票（3 个 6px 实心小方块，模型色）
        ╰─ 悬名标签（前排）
```

| 元素 | 说明 |
| --- | --- |
| 底盘 | 椭圆 `28×16`，模型色 12% 填充 + 1px 模型色 30% 描边；出局时整体下沉 4px 且去色 |
| 环 | 直径 44px 的 1.5px 圆环，模型色。默认 30% 透明度 |
| 机器人头 | 复用现有 `TopPiece` 组件，但改绘法：**去掉搪瓷填充，只留描边 + 发光面罩**，线宽 1.6px，模型色。形成"全息头像" |
| 名字 | 13px / 600，`--ink`，旁边一条 1px 引导线连回座位 |
| 票位 | 每得 1 票加一个小方块，最多显示 5 个，超出显示 `+N`（mono 10px） |
| 席位号 | 底盘左下角 mono 10px 的 `01`~`16`，与名册页一致 |

### 5.4 座位状态矩阵

| 状态 | 环 | 头纹 | 底盘 | 名字 | 附加 |
| --- | --- | --- | --- | --- | --- |
| 存活 idle | 模型色 30% 1.5px 实线 | 常态 | 常位 | `--ink-2` | — |
| 思考 thinking | 同色，**断续旋转**（8 段虚线，`4s/圈`） | 面罩熄灭 | 呼吸缩放 1.0↔1.03 | `--ink-2` | 座下地面有一圈 4s 扩散的淡光 |
| 发言 speaking | 模型色 **100% 2px 实线** + 12px 外辉光 | 面罩点亮，带 1.4s 明暗呼吸 | 底盘亮起，模型色 26% 填充 | `--ink` | 升起光柱，见 5.5 |
| 领先 lead | 环外再加一圈 1px 偏移 3px 的副环（模型色 50%） | — | — | `--ink` | 副环缓慢逆时针 20s/圈 |
| 平票 tied | 环变为双线（内外两圈 1px，间距 3px） | — | — | `--ink` | 副环 2.4s 呼吸一次 |
| 危险 danger（票最低且差距 > 1） | 环变 `--danger` 1.5px | 面罩变品红 | 底盘边缘 8% 危险色 | `--ink-2` | 无闪烁（避免误读为"正在发生"） |
| 出局 out | 环**断裂**（一段 60° 的缺口） | 全部去色 | 下沉 4px，模型色降到 0 | `--ink-3` + 删除线 | 席位号保留（表示"这个位置曾经属于谁"） |
| 胜者 winner | 环 100% + 旋转的 12 段刻度冠 | 面罩点亮 | 底盘亮起 | `--ink` | 桌心升起一柱光 |

### 5.5 发言光柱与投影面板

**光柱**：从发言者座位垂直升起的一道半透明梯形光（宽 34px → 顶部 22px），`linear-gradient(to top, rgba(61,232,192,.32), transparent)`，`filter: blur(6px)`。柱内有 6 颗缓慢上浮的粒子（3px 发光点，`4~7s` 不等周期）。光柱顶部有一条 1px 亮线。

**投影面板**（屏幕平面，居中偏上，宽 `min(760px, 72vw)`）

```
┌─────────────────────────────────────────────────────┐
│ ◍ GPT-5        独立发言 · gpt-5          剩余 02:14  │  ← 头部 44px 高
├─────────────────────────────────────────────────────┤
│                                                     │
│  【观点】……文字在这里流式显现……                     │  ← 16px / 1.85
│                                                     │
└─────────────────────────────────────────────────────┘
```

- 面板底：`--glass` + `backdrop-filter: blur(10px)`（这一处可以用毛玻璃，全站仅此一处）+ 1px `--hairline-strong` 描边 + 内侧 1px 顶部亮边。
- 面板顶部有一条从左向右生长的青色进度线，宽度 = 本轮剩余时间比例，剩余越少颜色越偏品红（`color-mix`）。
- 文字以**每 45ms 吐 6–9 个字**的方式流式显现（不是逐字打字机，太碎）。用 `requestAnimationFrame` 按字符数切片追加，不要对已渲染文本做逐字重渲染。
- 文字颜色 `--ink`，带极轻辉光 `text-shadow: 0 0 18px rgba(61,232,192,.22)`。**长段落辉光不得超过 22% 强度**，否则阅读发糊。
- 光标：面板末尾一个 2×16px 的青色竖条，1.1s 明暗呼吸。
- 面板边缘每 4s 从上往下扫过一条 2px 的水平扫描线（透明度 .12），持续运动直到该段发言结束。
- **故障感**：每约 120 个字符随机出现 1 次单字符错位（`transform: translateX(2px)` + 透明度 .6，持续 60ms）。频率上限：整段最多 3 次。这是"全息"质感的关键，但必须克制。
- 发言结束：扫描线停止、边框亮度提升一档（220ms）、面板头部出现一个 `已归档` 的 mono 微标签 + 一个小勾。
- 等待态（模型还在 thinking，无文本）：面板显示 `GPT-5 正在整理观点` + 三个递增亮度的方点（0.5s 循环），面板整体透明度 .72。

**谁在说话**：发言者座位升起光柱的同时，光柱顶端与面板底部之间画一条 1px 虚线引导线（dash 6/6，青色 30%），从面板底部扫到座位中心，300ms 内画出。上一个发言者的光柱同时塌陷（向下收回，260ms `--ease-in`）。

### 5.6 投票可视化（这场戏的高潮）

投票分三个阶段，各自有明确动作：

**阶段 A · 开始投票**（`voting_start` 事件）
1. 全场座位环降到 35% 亮度（260ms）。
2. 一道扫描线从桌面左端扫到右端（600ms，`--ease-out`）。
3. 扫描过后，每个投票人座位依次（间隔 60ms）闪一次自己的颜色。

**阶段 B · 每一票抵达**（`voting` 事件，status=done）
1. 从投票人座位画一条**弧线**到被投者座位。弧线不是直线——它沿桌面边缘走一段圆弧再收进目标座位（用 SVG 三次贝塞尔，起点切向沿座位角方向）。描边动画 420ms `--ease-out`。
2. 弧线颜色 = 投票人身份色，透明度 .75；被投座位环闪一次白。
3. 被投座位的票位增加一个小方块（弹入，`--ease-spring`，180ms）。
4. 桌心实时显示票数条：`GPT-5 ▮▮▮  3 票`。

**阶段 C · 计票完成**（`votes` 事件）
1. 所有射线同时增亮到 100%，持续 400ms。
2. 淘汰制：被投者座位正上方**落下**一道白色光柱（400ms），随后该座位塌陷（见状态矩阵 out）。
   评选制：领先者座位**升起**一道金色光柱（`--live`），其余射线淡出。
3. 桌心的票数条定格，随后整圈计数弧（环形进度）顺时针补完，数值滚动到最终票数。

**加赛（tiebreak）**：平票发生时，桌面上叠一层 `--danger` 8% 的红色薄膜，边缘出现一道缓慢扫描的红线，参与加赛的座位环同时变红并开始 1.6s 呼吸。加赛投票走**虚线射线**（与普通实线区分）。

**淘汰瞬间（elimination）**：
1. 白色光柱收缩到只剩一个点。
2. 座位环沿缺口处"碎裂"：环的描边 `stroke-dasharray` 从断口向两侧快速收回（260ms）。
3. 座位整体下沉 4px、去色、辉光熄灭（300ms `--ease-in`）。
4. **剩余座位向缺口合拢**：所有存活座位的角度重新均分，位置用 `--dur-slow` 720ms `--ease-spring` 过渡到位——这是整个页面最有"活着"感的一个动作，务必实现。
5. 名字标签保留删除线与席位号，并在标签右侧加一行 mono 小字 `第 N 轮出局 → 评审席`。评审身份由此自然可见。

### 5.7 席位与赛程的持久映射

**参赛模型的席位号在比赛全程不变**，由登记顺序决定。名册页、圆桌、记录页都显示同一个席位号 `01/02/...`。这样用户在"登记"页看到"GPT-5 是 03 号席"，到会场就能一眼找到。

### 5.8 开场序列（唯一的一次编排动效，约 2.4s）

`run_start` 触发后：

1. 0–400ms：全黑，只剩桌心的一个青色准星点，极缓慢扩张。
2. 400–900ms：桌面边缘环由中心向两侧展开（`stroke-dasharray` 生长），同时体积光柱落下。
3. 900–1400ms：3 圈刻线环依次旋转到位（每圈错开 120ms）。
4. 1400–2100ms：**座位按发言顺序沿圆环逐个点亮**，每个间隔 90ms，点亮时该座位底盘闪一下。
5. 2100–2400ms：HUD 顶条自上而下淡入；桌面外圈出现一行 mono 提示 `第 1 轮 · N 位参赛`。

之后进入常态，**不再有全局动画**。

### 5.9 圆桌的状态信息（取代旧版所有面板）

旧版的 `board-strip` / `live-speech-board` / `claims-bar` / `vote panel` 全部并入场景：

| 旧元素 | 新位置 |
| --- | --- |
| 命题 | HUD 顶条左侧，20px/700，`--ink`，超长省略号 |
| 赛制 / 限时 / 存活人数 / 轮次 | HUD 顶条右侧，mono 12px，`--ink-3`，用 `·` 分隔 |
| 总计时 | HUD 顶条右端，mono 16px/500，`--ink`，`tabular-nums`，沿用现有 `RollingNumber` 组件（数字滚动保留，这是个好交互） |
| 当前发言正文 | 投影面板 |
| 本轮所有主张 | 桌面中心下方一行"主张带"：每个模型一条 2px 高的色条 + 名字首字，悬停展开该模型的观点摘要（280ms 展开），点击跳到该模型的记录 |
| 票数 | 桌心下方一行实时票数条 |
| 回放控制 | 屏幕底部居中一条细轨道（保留现有 `⏮ ▶ ⏭` + 刻度点 + 倍速），样式改为发丝线 |

### 5.10 桌面居中区域的信息

桌心（准星位置）默认只显示一个 12px 的十字准星 + 极淡的 `ARENA` 微缩字样。当有投票时，这里变成票数汇总：

```
   GPT-5   ▮▮▮▮▮  5
   Claude  ▮▮      2
   ─────────────────
   共 7 票
```

用 mono 数字 + 模型色的实心小方块（复用现有 `TallyMarks` 组件的视觉语言但改成方块）。桌心文字始终很小（11–12px），因为它要能被桌面上的所有座位看到。

## 11. 文案规范

**语气**：平实、主动、具体。像一个赛事解说在平静地报事实，不要营销腔。

**原则**
- 按钮文字写清楚会发生什么：`开始比赛` / `登记模型` / `保存修改` / `换一个外观` / `查看这场`。不写 `提交` / `确定` / `了解更多`。
- 同一动作全程同名：`开始比赛` 之后就不要出现 `立即体验`。
- 错误不道歉、不含糊：`远程连接失败，模型 ID 可能是错的。` 而不是 `操作失败`。
- 空状态是邀请，不是道歉：`还没有存下任何一场争论。` + 一步动作。
- **禁止**：中点分隔的元信息串（`A · B · C`）、全大写小标签、`→` 跟在链接后、感叹号、emoji、`哦` `呀` `呢` 语气词。

**本项目专用文案表**（可直接用）

| 位置 | 文案 |
| --- | --- |
| 首页标题 | `让几台机器，把问题争论清楚。`（保留，是全站最好的一句） |
| 命题 placeholder | `写下一个值得争论的命题` |
| 命题提示 | `⌘↵ 开始比赛` |

## 13. 布局与排版骨架

**会场页**
- `.council`：全出血，`min-height: calc(100vh - 56px)`，`position: relative`，`isolation: isolate`。
- `.council__table`：`position: absolute; left: 50%; top: 56%; transform: translate(-50%,-50%) rotateX(56deg); transform-style: preserve-3d;`
- `.council__seats`：`position: absolute; inset: 0; transform-style: preserve-3d;` 座位用 `translate3d(x, y, z)`，z 由前后排区分（后排 `translateZ(-90px)`，前排 `translateZ(40px)`），这是比 `scale` 更有纵深感的做法。
- `.council__panel`：屏幕平面，`position: absolute; left: 50%; top: 6%; transform: translateX(-50%);` 不参与 3D。
- 移动端（< 860px）：桌面缩到 `min(560px, 88vw)`，座位头像缩到 32px，名字只显示席位号，投影面板移到桌面下方全宽，HUD 顶条折成两行。座位超过 8 人时只显示前排 + 后排中间三席，其余折叠为桌心一个 `+5` 标记（点击展开列表）。

**其他页**
- 容器 `max-width: 1360px; margin: 0 auto; padding: 0 32px;`
- 记录页三栏：`grid-template-columns: 200px minmax(0, 1fr) 320px;` 中栏内部 `max-width: 680px`。
- 档案页台账：表格全宽，行高 44px。

## 14. 性能与可达性

**性能**
- 只动 `transform` / `opacity` / `filter`。不要在动画里改 `width/height/top/left`。
- 桌面的辉光、扫描环用 CSS `conic-gradient` + `mask`，不要用 canvas 逐帧。
- 射线用 SVG（数量少，≤ 16 条），不要用 canvas。
- 投影面板文字流式追加：用**增量拼接**（只 push 新字符到数组，Vue 用 `v-for` 渲染段落），不要每帧重新 `v-html` 整个文本。
- 辉光层用 `will-change: transform` 的数量控制在 5 个以内；超出的用 `filter: blur()` 静态替代。
- 目标：1440×900 下圆桌场景稳定 60fps。

**可达性**
- 所有可交互元素键盘可达，`:focus-visible` 用 2px `--live` 描边 + 2px offset。
- 状态不能只靠颜色：出局=删除线+断裂环+下沉，领先=双环，平票=双线环，危险=名称旁一个 `票数最低` 的 mono 提示。
- 投影面板用 `aria-live="polite"` 流式播报（但节流为整段而不是逐字）。
- 座位元素给 `role="img"` + `aria-label="GPT-5，席位 03，正在发言"`，屏幕阅读器可读出当前局势。
- `prefers-reduced-motion: reduce` 下所有动效降级为透明度/颜色切换，座位重排改为瞬时，粒子与扫描线停止。
