# Agent Arena · 界面设计规格 v2

> 配套文档：`docs/product-redesign-v2.md`（功能设计）。本文只管**界面**：新功能长什么样、放在哪、怎么动。
> 基线：现有实现即 `docs/frontend-redesign.md` 的落地版（`static/app.js` 2366 行 + `static/style.css` 2960 行 + `templates/index.html` 601 行，五页：登记/会场/记录/档案/模型）。
> 视觉语言**不重开**：沿用全息议事舱（`--void #04070A` / `--live #3DE8C0` / `--danger #FF3D6E` / 6 色模型身份色 / Space Grotesk + IBM Plex Mono / 零软阴影 / 发丝线）。**这次是加零件，不是换整车。**

---

## 0. 一句话设计命题

> **从"看一场戏"变成"读一份资产"。**

v1 的界面服务的是**过程**（谁在说、谁在投、谁出局）。v2 要在过程之上长出三类**结果物**：可比较的**评分**、可追溯的**主张台账**、可复用的**对比**。所以这次设计的主线不是加页面，是**给已有的五个页面各挂一个"结果出口"**，并且让过程本身看得更快（并行）、看得更准（加权票权）、看得更省（预算、收敛）。

## 1. 设计系统层面的四条新增约束

### 1.1 不新增色相 —— 状态一律用形状和明度表达

原文档的铁律是"颜色属于模型，不属于界面"。6 色模型身份色是：

```
#FFB020 琥珀   #7C6BFF 紫罗兰   #46D0FF 冰蓝
#C8F04A 黄绿   #FF6E4A 余烬橙   #A8B4C4 钢灰
```

界面语义色只有 `--live`（青）、`--danger`（品红）、中性灰蓝三色。v2 新增的状态很多（主张采纳/未定/已否定、预算正常/吃紧/超限、收敛/分歧、评审/存活票），**如果每个都配一个色相，必然开始和模型身份色打架**——琥珀、余烬橙、紫罗兰都在候选名单里。

**决定：v2 不增加任何新色相。** 新状态全部用既有手段表达：

| 状态 | 颜色 | 形状/线型 | 文案 |
| --- | --- | --- | --- |
| 主张被采纳 | `--live` | 2px 实线左脊 | `采纳` |
| 主张未决 | `--ink-2` | 1px 虚线左脊 | `未决` |
| 主张被否定 | `--ink-3` | 删除线 + 无脊 | `已否定` |
| 保留的分歧 | `--danger` | 1px 虚线框（区别于实心的危险实心块） | `未解决` |
| 失效条件 | `--ink-2` | 左侧 2px `--ink-3` 实线 | `前提` |
| 预算吃紧 | `--live` → `--danger` 渐变 | 细条填充色 | `接近上限` |
| 评审票 | `--ink-2` | 半高方块（区别于整块） | `评审` |
| 存活票 | 模型色 | 整块 | — |

唯一允许"新增"的视觉是**明度阶梯**：分数热区用 `--live` 的单色渐变（0-10 分映射 `--live-dim` 0% → 100% 透明度），不引入第二个色相。这与 v1 "信息密度靠明度层级而不是色相数量去撑"完全一致。

### 1.2 新增五个设计令牌（只加不加）

```css
  --live-weak: rgba(61, 232, 192, .08);   /* 分数热区第 1 档 */
  --ink-4: #4A5C6E;                       /* 比 --ink-3 更弱：删除线态的正文 */
  --seat-judge: rgba(159, 182, 196, .34); /* 评审席位环降亮后的替代描边 */
  --budget-track: rgba(120, 170, 200, .12);
  --focus-halo: rgba(61, 232, 192, .28);  /* 键盘聚焦环，比 --live-glow 柔 */
```

理由：`--live-weak` 撑起评分矩阵的 10 档热区；`--ink-4` 让"已否定"的主张真的退到背景里；`--seat-judge` 让评审席位在圆桌上比存活者弱半档（**评审还在，但已经不在桌上了**）；`--budget-track` 和 `--focus-halo` 是功能件。

### 1.3 数字一律用等宽 + `tabular-nums`

评分、票数、token、轮次、耗时全部是"要能被扫读比较"的数字。规则：

- 评分：10 分制 → 显示 `7.4` 一位小数（不是整数，因为聚合后取平均必然产生小数）；
- 票数：加权后会出现 `2.5`，**必须显示一位小数**，且 `2` 显示为 `2.0`（列对齐比好看重要）；
- token：`12,480` 千分位；
- 耗时：`4m12s`（沿用现有 `durationText`）；
- 全部 `font-family: var(--mono)` + `font-variant-numeric: tabular-nums`。

### 1.4 表格语言优先于卡片语言

v1 已经定调"不用卡片堆、用发丝线和背景明度差"。v2 新增的评分矩阵、主张台账、对比视图、模型画像**全是密集数据**——这四个新界面**一律用表格 / 台账，不用卡片**。这是 v1 档案页"赛事台账"决策的延续，不是新规则。

## 2. 新的可视化原语（四个新组件）

v1 已有组件：`RobotAvatar` / `TopPiece` / `RollingNumber` / `TallyBlocks` / `Segmented` / `DataTable`(档案台账)。v2 需要四个新的。

### 2.1 `WeightedTally` —— 加权票位（替代 `TallyBlocks` 的新用法）

**要解决的问题**：评审票权重 0.5，计票出现小数。现有 `TallyBlocks` 是整数方块。

**形态**：一排方块，**整块 = 1.0 票，半高方块 = 0.5 票**。

```
存活票整块 ▮▮▮▮   评审半块 ▪▪
```

- 整块：6×6px，`--team-color` 填充；
- 半块：6×3px，靠下对齐（贴着整块底部），`--ink-2` 30% 填充 + 1px 描边；
- 超过 5 个显示 `+N`（沿用 v1）；
- 数值右侧 `2.5` 用 mono。

**为什么这样而不是画半透明整块**：半透明会和"半亮度的存活票"混淆，而半高方块是形状差异，扫一眼就分得清。**形状优先于透明度**——这条和"颜色属于模型"是同一个原则。

**评审席的特殊处理**：在圆桌座位上，评审的票位框加 1px `--seat-judge` 描边并整体降亮（`opacity .72`），与存活席区分。

### 2.2 `ScoreMatrix` —— 四维评分矩阵

**要解决的问题**：四维评分（论证/证据/可执行/增量）× N 个模型，需要一个能横向比较的密集视图。

**形态**：**表格，不是热图卡片**。

```
              论证   证据   可执行  增量   均分
知微          ▓▓▓▓░  ▓▓▓░░  ▓▓▓▓▓  ▓▓░░░   7.4
星澜          ▓▓░░░  ▓▓▓▓░  ▓▓▓░░  ▓▓▓░░   6.6
小码          ▓▓▓░░  ▓▓░░░  ▓▓▓▓▓  ▓▓░░░   6.2
```

- 每格 = 一个 5 段（`▓`/`░` 字符或 CSS 格子）微条 + 数值；微条填充用 `--live` 单色明度阶梯（按分数档位取 `--live` 透明度 20%/40%/60%/80%/100%）；
- 最后一列 `均分` 是关键列，2px `--live` 左脊标出当轮最高分；
- 表头是维度名 + 一句话释义（悬停 `title`）：`论证 = 论据链条是否成立`；
- 排序：**默认按均分降序**，但每个表头可点击切换排序（做对比时顺序必须可控）。

**在圆桌上的呈现**：不做完整矩阵。桌心在投票完成后短暂显示**当轮均分前二 + 分差**（`知微 7.4 · 星澜 6.6 · 分差 0.8`），1200ms 后淡出。理由：圆桌是"看局势"的，矩阵是"看数据"的，塞满会毁掉场景。**详细矩阵只在记录页和对比台出现。**

### 2.3 `ClaimLedger` —— 主张台账（旗舰组件）

**要解决的问题**：主张台账是 v2 最重要的产出物，但它必须能读，不能只是一堆文本。

**形态 A：台账表（默认）**

```
┌──────────────────────────────────────────────────────────────────────┐
│ 主张台账                                          [台账] [谱系]     │
├────┬──────────────────────────────┬──────┬────┬────────────┬──────┤
│ #  │ 主张                         │ 提出 │ 轮 │ 被谁挑战   │ 结局 │
├────┼──────────────────────────────┼──────┼────┼────────────┼──────┤
│ 01 │ 先收定金再交付，不要免费定制  │ 星澜 │ 2  │ 小码 知微  │ 采纳 │
│ 02 │ 效果分成需要可审计的归因口径  │ 小智 │ 2  │ 知微      │ 未决 │
│ 03 │ 服务即研发，从付费里长产品   │ 小码 │ 3  │ 星澜      │ 已否定│
│ 04 │ 单客贡献毛利比客户数更重要   │ 小码 │ 4  │ 星澜 知微 │ 采纳 │
└────┴──────────────────────────────┴──────┴────┴────────────┴──────┘
```

- 主张列 = 一句话原子命题，15px，最多 2 行截断，悬停展开全文；
- **结局列用左脊编码**：采纳 = 2px `--live` 实线；未决 = 1px `--ink-2` 虚线；已否定 = 无脊 + 删除线 + `--ink-4`；
- **被谁挑战列**：模型小方块（各模型身份色），横向排，最多 4 个，超出 `+N`；
- 默认排序：**提出轮次升序**（这是辩论的叙事顺序，也是台账的价值来源）；
- 顶部三个计数：`采纳 2 · 未决 1 · 已否定 1`，用 mono，采纳数为 `--live`。

**形态 B：谱系（`谱系` 切换）**

这是台账真正的杀手锏——**看清一条主张是怎么被改掉的**。

```
  轮1          轮2              轮3             轮4
  ┌───┐
  │星澜│──主张01──┐
  └───┘          │
      ┌──────────┴───────────┐
      │ 小码:「转包扩容」      │  ← 挑战
      │ 知微:「承保兜底」      │
      └──────────┬───────────┘
                 │
                 ▼
            ┌─────────┐
            │ 未决      │  ← 到终局仍无定论
            └─────────┘
```

- 纵向 = 轮次（左侧轮次轨，1px `--hairline`），横向 = 主张的演化分支；
- 每条主张一个节点：`8px` 圆点 + 提出者色环；被挑战时从节点分出一条 1px `--ink-3` 支线到挑战者节点；
- 结局：节点右侧标 `采纳`（`--live` 实心小方块）/ `未决`（空心）/ `已否定`（删除线）；
- **被采纳的主张加一条 `--live` 竖线贯穿到最右边的"最终裁决"列**——一眼看到哪些观点活到了最后；
- 复杂度控制：**只渲染被挑战过的主张的谱系**（没有挑战的主张就是一条直线，不占地方）。

**为什么"谱系"值得做**：单看台账，你只知道"主张 02 未决"；看谱系，你知道"它是被小码和知微两个人从不同角度挑战后悬而未决的"——**这才是决策者真正需要的风险信息**。

### 2.4 `SpreadGauge` —— 立场离散度计

**要解决的问题**：后端要按立场极差（max-min）判断收敛/分歧，界面必须让这个数可见，否则"提前收束"看起来像 bug。

**形态**：HUD 顶条右侧一个 72px 宽的横向计。

```
立场离散  ▓▓░░░░░░  23   收敛阈值 25
```

- 填充 = `极差 / 100`，用 `--live` 单色；
- 阈值 25 处一条 1px `--ink-2` 竖刻线；
- 极差 ≤ 25（收敛）时填充转 `--live` 并在右侧显示 `已收敛`；极差 ≥ 150（分歧过大）时显示 `--danger` 的 `分歧大`；
- 平时（无 stance 数据时）**整个计隐藏**，不占位。空数据不显示空控件。

## 3. 逐页设计

### 3.1 登记页（`register`）—— 三处改动

#### 3.1.1 命题从单输入框变成"结构化命题"

**问题**：后端要接收 `question / background / constraints / criteria` 四段，前端还是一个 textarea。

**形态**：命题区从单个 48px 输入框变成一个**四段折叠组**，默认只展开第一段：

```
今天让它们争论什么？
┌────────────────────────────────────────┐
│ 远程办公是否应该永久化？                 │
└────────────────────────────────────────┘
⌘↵ 开始比赛        [＋ 背景与约束 4] [＋ 评判标准 3]

┌─ 背景与约束 ──────────────────── 展开 ─┐
│ 背景  [textarea 2 行]                   │
│ 约束  [可增删的短标签]                   │
└─────────────────────────────────────────┘
┌─ 评判标准 ────────────────────── 展开 ─┐
│ [×]  论据是否成立、能否验证              │
│ [×]  是否真的推进了命题、有无增量        │
│ [＋ 添加一条]                           │
└─────────────────────────────────────────┘
```

**关键决策**：
- **评判标准用标签组而不是 textarea**。因为评判标准要**逐条**参与投票打分，做成可增删的短标签，能直接对应"投票评分矩阵"的维度列。用户写 3 条标准 → 评分矩阵就是 3 维。**前后端字段一一对应**，这是设计上的硬约束。
- **标签用 chip 形态但要克制**：1px `--hairline-strong` 描边 + 12px 字 + `--ink-2`；聚焦新标签时描边转 `--live`。删除用 `×`，不是垃圾桶图标。
- 折叠组的展开箭头用 `▸`/`▾`（v1 禁用 emoji，但几何字符允许），旋转 120ms。
- 背景与约束里的"约束"也用标签组（短文本），"背景"用 textarea。
- **这一段收在第一段下面，不做弹窗、不做独立页**。理由：命题的 80% 使用场景只有一句话，折叠组的价值是"需要时才展开"，不是"展示全部字段"。

#### 3.1.2 规则区扩成"赛制设置"

现在右上角是「淘汰制/评选制 + 限时秒数」。v2 要加并行模式、预算。

```
┌─ 赛制 ──────────────────────────────┐
│ [淘汰制 | 评选制]                     │
│ 投给观点最站不住的一方，票多者出局      │
│                                       │
│ 发言方式  [并行生成 | 逐个实时]         │
│ 并行：同时生成，本轮结束后按席位回放     │
│                                       │
│ 限时 [240] 秒                          │
│ 预算 [20000] token  [不限]             │
└───────────────────────────────────────┘
```

- **发言方式是一个分段控件**，两个选项，右侧一行 12px `--ink-3` 说明随选项切换（沿用 v1 规则说明的交叉淡入手法）；
- 预算输入两个字段：token 上限 + 调用次数上限，任一超出即收束。**默认留空 = 不限**，但留空时旁边要有 12px `--ink-3` 的提示：`不限预算时，单场可能产生较多调用`；
- 这一整块仍然贴在页面右上角，但**宽度从现在的窄条变成 280px 侧栏块**，用 1px `--hairline` 与页面主体分隔。

#### 3.1.3 名册行增加"人格"标记

v2 后端支持给每个模型分配辩论人格（审计员/务实派/反方/红队/归纳者）。

名册行在模型 ID 之后加一列 `人格`，显示一个 mono 小标签：

```
01  ◍  GPT-5    gpt-5        [务实派]   ✓参赛   修改 删除
```

- 未分配时该列为空（**不显示"无"**，空就是无）；
- 人格标签用 1px `--hairline-strong` 描边 + 10px mono + `--ink-2`，**不用彩色**（人格不是身份色，是行为修饰）；
- 鼠标悬停标签出 `title`：`务实派 · 只看落地成本`。
- **人格只影响发言，不影响投票**——这是产品的公平性底线，界面上必须让人看到（见 3.2.4）。

### 3.2 会场页（`venue`）—— 四个新增区域

会场页是全出血场景，**新增的东西必须挂在已有的层级体系里，不能破坏"一个 memorable，其余安静"**。v1 已有 8 层（L0 背景场 → L8 HUD）。v2 的新东西：

#### 3.2.1 L2.5 新增层：`生成矩阵`（并行模式专用）

**这是 v2 会场页最重要的新增视觉。**

**问题**：并行模式下 N 个模型同时生成，但 v1 的投影面板一次只显示一个发言者。如果什么都不改，用户会以为卡住了。

**形态**：在投影面板的位置（`--council__panel`，屏幕平面，居中偏上）放一个**生成矩阵**，宽 `min(760px, 72vw)`：

```
┌─────────────────────────────────────────────────────────────┐
│  第 2 轮 · 6 位并行生成中                            3/6 完成 │
├─────────────────────────────────────────────────────────────┤
│  ◍ 知微    ▓▓▓▓▓▓▓▓░░░░░░░░░░░░   1,842 字      生成中     │
│  ◍ hy3     ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   2,103 字      完成       │
│  ◍ 星澜    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░   1,655 字      生成中     │
│  ◍ 灵溪    ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░   1,410 字      生成中     │
│  ◍ 小码    ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓   2,344 字      完成       │
│  ◍ 小智    ▓▓░░░░░░░░░░░░░░░░░░░░░     412 字      生成中     │
└─────────────────────────────────────────────────────────────┘
```

设计要点：
- **不显示任何发言内容**。只显示：头像 + 名字 + 进度条 + 字数 + 状态。因为并行时其他人的发言还没公开，**泄露半句话就是破坏赛制**。字数是进度信号，不是内容。
- 进度条 = 已收到字符数 / 本轮预估最大字符数（用历史同轮平均字数做分母；首轮用 2000 字兜底），或者更简单：**按 0-100% 映射到"本场该模型历史发言长度的中位数"**。实现上用后者更稳。
- 状态三态：`生成中`（进度条呼吸）、`完成`（进度条转 `--live` 实心 + 勾）、`等待服务商`（灰 + 计时）。
- **完成度计数 `3/6` 放在标题栏右侧**，mono 16px。
- **完成即锁定**：完成的行不再变化（进度条停止），只有未完成的在动。这让画面有"陆续落定"的节奏。
- 面板底部一行 12px `--ink-3`：`并行生成中，本轮结束后按席位顺序回放`。

**流转**：
1. `round_start` → 投影面板淡出（260ms），生成矩阵从下方升起（420ms）；
2. N 个模型同时进入 `thinking` 状态 → **圆桌上所有存活席位的环同时转为断续旋转**（这是"真的并行"最直接的视觉证据）；
3. 每完成一个 → 该行锁定 + 顶部计数 +1；
4. 全部完成 → 生成矩阵整体上移淡出（420ms），投影面板从原位降下（420ms），进入**回放阶段**：按 `record.order` 顺序逐个播放发言，**播放时圆桌只让当前模型的光柱升起**（其余席位的环回到 idle）。

**关键**：回放阶段必须让用户知道"这不是实时了"。做法是 HUD 状态文字显示 `回放中 · 第 2/6 位`，并在生成矩阵消失时留一个 4 秒后淡出的 mono 微条 `本轮为并行生成，正在回放`。

#### 3.2.2 L8 HUD 新增三个读数

HUD 顶条右侧现在是「赛制 · 限时 · 存活人数 · 轮次 + 总计时」。v2 加三个：

```
┌────────────────────────────────────────────────────────────┐
│ 命题：远程办公是否应该永久化   淘汰制 · 3人存活 · 第2轮      │
│                                    立场离散 ▓▓░░ 23   12,480 tok │
└────────────────────────────────────────────────────────────┘
```

- **立场离散计**（`SpreadGauge`，见 2.4）：72px 宽，紧凑嵌在 meta 行；
- **预算读数**：`12,480 tok`，mono 12px `--ink-3`；超过 80% 转 `--live`，超 100% 转 `--danger`；
- **轮次读数**保持原样。

HUD 顶条高度从 56px 增加到 **68px**（容纳第二行读数）。左中右的分区不变。

#### 3.2.3 L8 HUD 新增一个动作：`停止`

```
                                        ⏹ 停止本场
```

- 右上角，12px mono `--ink-3`，hover 转 `--danger` + 出现 1px `--danger` 描边；
- **点击不弹窗**，直接二次确认（按钮本身变成 `--danger` 实心 + 文案变 `确认停止`），3 秒无操作自动还原。理由：v1 文案规范明确"不要弹窗"，而二次确认按钮比弹窗轻；
- 停止后：当前模型调用中断 → 场景整体亮度降一档 → HUD 显示 `已停止 · 保留已完成轮次` → 自动跳到记录页。

#### 3.2.4 人格可见性（公平性提示）

**这是必须做的信任设计。** 人格预设会强制某些模型"唱反调"，如果用户不知道，投票结果的可信度就被污染了。

- 发言时：投影面板头部显示 `◍ 小码  红队 · 攻击最强论点  gpt-5`（人格用 `--ink-3` 小字）；
- **投票环节**：投影面板/投票区显示一行 `--ink-3` 12px：`投票环节不套用人格，全部按证据判断`；
- 记录页每条发言头部也标人格；
- 战报 Markdown 里人格标注在阵容表。

### 3.3 记录页（`record`）—— 三栏扩成四段 + 一个新区域

v1 记录页是三栏：`轮次轨（左）· 发言正文（中）· 投票与裁决（右）`。

v2 在右栏里塞评分矩阵会把右栏撑爆，而且**评分是"跨轮"的、投票是"本轮"的**，混在一起读起来乱。

#### 3.3.1 结构改为：轮次轨（左）· 发言（中）· 本轮裁决（右）· 全局资产（下）

```
┌──────────┬──────────────────────────┬───────────────────────┐
│ 轮次      │  第 2 轮 · 3 人存活        │ 第 2 轮 · 投票与裁决   │
│ ──────── │  GPT-5 → Claude → Gemini  │ ─────────────────────│
│ ● 第 2 轮 │  ┌────────────────────┐  │ 票数（加权）           │
│   3 人存活 │  │ ◍ GPT-5            │  │ 知微 ▮▮▮▮  3.0      │
│   出局 X  │  │ 【观点】…          │  │ 星澜 ▮▮▪   2.5      │
│ ○ 第 1 轮 │  └────────────────────┘  │ ─────────────────────│
│   4 人存活 │                          │ 评分矩阵               │
│           │                          │ 知微 7.4 ▓▓▓▓░       │
│           │                          │ 星澜 6.6 ▓▓▓░░       │
│           │                          │ ─────────────────────│
│           │                          │ 选票明细               │
│           │                          │ 知微 → 星澜            │
│           │                          │ 「理由…」             │
├──────────┴──────────────────────────┴───────────────────────┤
│  主张台账  [台账] [谱系]                                     │
│  01 先收定金再交付…  星澜 · 第2轮 · 被 小码 知微 挑战  [采纳]  │
└──────────────────────────────────────────────────────────────┘
```

**决策**：主张台账放在**记录页底部通栏**，而不是新开一个页面。理由：
1. 台账是"这场辩论的资产"，天然属于这场记录；
2. 新开第六个页面会让顶栏导航变长（现在 5 项已占满），且违背 v1 "五个页面"的结构稳定性；
3. 通栏的宽度正好容纳台账表的多列。

#### 3.3.2 评分矩阵在右栏的呈现（局部化）

右栏只显示**当轮**评分，且**只显示均分 + 2 个最高维度**，完整四维矩阵在主张台账区上方以"展开"形式提供。

理由：右栏宽度 320px，塞四维矩阵会让每格只剩 40px，读不出差异。**右栏给"结论"，通栏给"明细"。**

具体：
- 右栏评分区标题 `本轮评分`，一行一个模型：`知微  7.4  ▓▓▓▓░`，按均分降序；
- 每行右侧 `+` 按钮 → 展开该模型的四维明细（`论证 8 · 证据 6 · 可执行 9 · 增量 7`）；
- 表格底部一行 `--ink-3` 12px：`完整矩阵 · 12 人次投票的原始打分见战报 JSON`。

#### 3.3.3 选票明细的"权重透明化"

现在选票行是 `投票人 → 被投者` + 理由。v2 加权重后必须让人看出这张票值多少：

```
知微 → 星澜                    1.0
  「方案趋同，缺新增量」

hy3（评审）→ 星澜              0.5
  「线索审计仍属旧范畴」        评审票 · 权重 0.5
```

- 存活投票人：右侧不显示权重数字（默认 1.0，不必占位）；
- 评审投票人：左侧 1px `--danger` 竖条（沿用 v1）+ 名字后加 `（评审）` + 理由下面一行 `--ink-3` 12px `评审票 · 权重 0.5`；
- **理由文本不再截断**。v1 是 42 字折叠，v2 改成：≤60 字直接显示，>60 字显示前 3 行 + `展开`（v1 已有的 `ballot__more` 机制，放宽阈值即可）。后端不再做 `[:40]` 截断，前端保留折叠是阅读需要，不是数据丢失。

#### 3.3.4 最终裁决：新增两个必备区块

后端 v2 的最终结论结构是 `【结论】/【论据】/【保留的分歧】/【失效条件】`。界面上必须给"保留的分歧"和"失效条件"**和结论不同的视觉待遇**——它们是风险信息，不是正文。

```
FINAL DECISION
知微

最优项目是面向投标代理及工业品经销团队的"投弃标决策工具"…

论据
1. 付费痛点是减少无效投标与筛选工时，结果可验收…
2. AI＋人工压低交付成本；聚焦单品类可复用规则…

┌ 未解决 ─────────────────────────────────────────┐
│ 星澜提出：未被及时跟进的询盘不等于可回收收入。    │
│ 未被采纳，也未被证伪。                           │
└──────────────────────────────────────────────────┘

前提
· 对方为当前已赚到钱的商家
· 首次部署需 3 家付费客户
```

- **保留的分歧**：1px `--danger` **虚线**框（区别于场景里的 `--danger` 实心块），内文 `--ink` 14px；每条注明提出者（模型色小方块 + 名字）；右上角一个 10px mono 标签 `未解决`；
- **失效条件**：左侧 2px `--ink-3` 实线，标题 `前提`（不用"失效条件"因为更短更准），每条一行 `--ink-2` 13px；
- 框与框之间 24px。

**为什么这两块必须视觉上"脱离"正文**：正文是"模型认为的答案"，这两块是"这个答案在哪儿会失效"。混排会让读者把风险当成结论的一部分滑过去。

### 3.4 档案页（`archive`）—— 从"台账"升级为"对比台"

v1 档案页是一张赛事台账表。v2 它要承担两件事：**历史检索** + **横向对比**。

#### 3.4.1 保留台账，增加一个"对比"模式切换


## 4. 事件 → 动效剧本扩展

v1 已有 21 个事件的动效表。v2 新增 8 个事件（后端配套），并修改 3 个已有事件的行为。

### 4.1 新增事件

| 事件 | 界面动作 |
| --- | --- |
| `parallel_start` | 投影面板淡出（260ms）→ 生成矩阵从下方升起（420ms，`--ease-out`）；圆桌所有存活席位环转 `thinking`（断续旋转） |
| `parallel_progress` | 对应行进度条推进 + 字数更新；状态 `生成中 → 等待服务商` 切换 |
| `parallel_done` | 该行锁定（进度条转 `--live` 实心 + 勾出现，180ms `--ease-spring`）；顶部 `3/6` 计数滚动 |
| `parallel_replay` | 生成矩阵上移淡出（420ms）；投影面板从原位降下（420ms）；HUD 状态文字 → `回放中 · 第 2/6 位`；出现 4s 后淡出的 mono 微条 `本轮为并行生成，正在回放` |
| `scores` | 桌心显示当轮均分前二 + 分差，1200ms 后淡出（不在圆桌显示完整矩阵） |
| `claims` | 记录页底部台账区追加行（新行用 240ms 淡入 + 左脊从 0 长到 2px）；若在对比台/台账页可见，同步追加 |
| `budget` | HUD token 读数更新；超过 80% 读数转 `--live`，超 100% 转 `--danger` |
| `stopped` | 场景亮度降一档（600ms）→ HUD 显示 `已停止 · 保留已完成轮次` → 1.2s 后自动跳记录页 |

### 4.2 修改已有事件

| 事件 | v1 行为 | v2 行为 |
| --- | --- | --- |
| `votes` | 票数用整数方块 | 票数改用 `WeightedTally`（整块/半块）；HUD 附近加一行 `--ink-3` 12px `存活者 3 票 · 评审 2 票（权重 0.5）` |
| `final` | 投影面板换成最终裁决版式 | 投影面板只显示 `【结论】`；**完整裁决（含保留的分歧/前提）落在记录页**，投影面板给一个 `查看完整裁决 ›` 的链接（跳记录页并滚动定位） |

## 6. 响应式

v1 断点：`< 860px` 圆桌缩到 `min(560px, 88vw)`，座位 >8 折叠；375px 下五页不横向溢出。

v2 新增组件的响应式规则：

| 组件 | < 860px | < 640px |
| --- | --- | --- |
| 生成矩阵 | 宽 `92vw`，每行只显示 头像+名字+进度条，字数折叠 | 只显示 名字 + 进度条，字数与状态折叠进 `title` |
| 主张台账（台账） | 隐藏"轮次"列，"被谁挑战"改为头像堆叠 | 变成**卡片式条目**（每条主张一格，标题 + 提出者 + 结局徽记）——这是唯一允许卡片化的场景，因为移动端表格必然横向滚动 |
| 主张台账（谱系） | 横向滚动的泳道，最少显示 3 轮 | **降级为台账视图**（谱系在移动端不可读，直接隐藏切换项） |
| 评分矩阵 | 4 维变 2 维（均分 + 最高维），完整矩阵进展开 | 只显示均分列 |
| 对比并排 | 从左到右滚动的卡片列（280px 一列），首列吸附 | 同上，每列 240px |
| 模型画像 | 表格横向滚动，冻结首列 | 改为**每个模型一个块**（名称 + 4 个关键数字） |

**硬性要求**：`375px` 下新增的所有区域不产生页面级横向溢出（`document.scrollWidth <= 375`）。

## 7. 可达性（WCAG AA）

| 对象 | 要求 |
| --- | --- |
| 生成矩阵 | `aria-live="polite"`，但**只播报完成数**（`3/6 完成`），不逐字播报字数 |
| 主张台账 | 用真 `<table>` + `<th scope="col">`；结局状态不能只靠颜色（同时有"采纳/未决/已否定"文字） |
| 谱系 | 每个节点 `role="img"` + `aria-label="主张 01，星澜提出，第 2 轮，被小码和知微挑战，未决"`；提供隐藏的 `<table>` 作为无障碍等价物 |
| 评分矩阵 | 每个格子有 `aria-label="知微 论证 8 分"`；微条本身 `aria-hidden` |
| 加权票位 | 整块/半块的形状差异必须同时有文字：`aria-label="3.0 票"`（不让屏幕阅读器读"3 个半块"） |
| 立场离散计 | `role="meter"` + `aria-valuenow` + `aria-valuetext="极差 23，收敛阈值 25"` |
| 预算读数 | `aria-live="polite"`，但节流到 10% 粒度（避免每 token 播报） |
| 停止按钮 | 可键盘操作；二次确认状态用 `aria-live="assertive"` 播报"再按一次确认停止" |
| 保留的分歧 / 前提 | 用 `<section>` + `<h3>`，不是纯 div；危险虚线框有 `role="note"` |
| 焦点可见 | 所有新增可交互元素 `:focus-visible` 用 2px `--live` 描边 + 2px offset；输入框聚焦用 `--focus-halo` 柔光环 |
| 动效降级 | `prefers-reduced-motion: reduce` 下：生成矩阵的进度条停止呼吸改为静态填充；并行回放改为瞬间切换；差异下划线直接显示 |
| 对比度 | 正文 ≥ 4.5:1、大字 ≥ 3:1。**注意** `--ink-4: #4A5C6E` 只用于 ≥18px 或非文字元素（它对 `--deck #0B1220` 的对比度约 3.1:1，不满足正文要求） |

## 8. 性能

| 关注点 | 规则 |
| --- | --- |
| 生成矩阵 | 6 个进度条 = 6 个独立动画元素，用 `transform: scaleX()` 而不是 `width`；`will-change` 数量 ≤ 6 |
| 进度更新 | 后端 `model_output` 高频到达时，**进度条更新节流到 100ms 一次**；字数文本节流到 500ms（避免每字符触发 Vue 重渲染） |
| 主张台账 | 追加式更新，不做全量 diff。行超过 200 条时虚拟滚动（先不做，但台账必须有条数上限提示） |
| 谱系 | 只渲染有挑战关系的主张；节点数上限 120，超出显示 `仅显示前 120 个节点` |
| 对比并排 | 同时最多 3 场；更多场次提示"一次最多对比 3 场" |
| 评分矩阵 | 单元格 ≤ 12×4 = 48 个，纯 CSS 背景，无 canvas |
| 颜色计算 | `agentColor` 的结果**缓存**（`Map`），不在渲染期反复算 hash |
